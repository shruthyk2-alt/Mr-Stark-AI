1. [FIXED] Voice input fragmentation

   - RequestError → show connection error → keep listening

   - Removed one-shot response generation from voice worker
   - All responses come from Gemini with StarkVoice system instructions
   - No hardcoded "Hey kiddo, what's the plan?" responses

   - Both text and voice modes now use send_console_prompt()
   - send_console_prompt() includes StarkVoice.system_instructions()
   - Gemini receives full MR. STARK personality for all inputs

5. [FIXED] Voice mode turns OFF after one utterance
   - Changed from one-shot worker to continuous listening loop
   - Worker emits utterance_captured signal, then returns to listening
   - voice_enabled stays True; worker keeps running
   - User must explicitly press "Voice: Off" to stop

6. [FIXED] Auto-return to LISTENING after TTS
   - speak_response() sets microphone_suppressed=True during speech
   - After TTS finishes, suppression flag is cleared
   - speak_response() emits update_voice_state("listening")
   - Worker detects listening state and returns to listening

7. [FIXED] MR. STARK's own voice being transcribed
   - Implemented microphone_suppressed flag in main window
   - Worker checks this flag in listening loop
   - While speaking, worker sleeps instead of listening
   - Prevents echo/feedback transcription

8. [FIXED] Separate pipelines for text and voice
   - Text input: QLineEdit → send_console_prompt()
   - Voice input: Microphone → STT → send_console_prompt()
   - Both converge to same unified Gemini handler
   - Shared conversation history
   - Single source of truth for AI responses

9. [FIXED] Thread safety and GUI responsiveness
   - VoiceCaptureWorker runs in QThread (background)
   - All signals emit to main thread (Qt-safe)
   - Microphone listening doesn't block GUI
   - TTS runs in speak_response() (called from GUI thread, but uses engine's async)
   - GUI remains responsive during all voice operations

10. [FIXED] Stop button not working properly
    - interrupt_voice() now properly signals worker to stop
    - Sets voice_stop_event to trigger worker loop exit
    - Waits for thread to quit (timeout 3 seconds)
    - Cleans up resources gracefully

VOICE PIPELINE ARCHITECTURE (NEW)
======================================================================

TEXT MODE:
  User types in QLineEdit
    ↓
  send_console_prompt()
    ↓
  Gemini API with StarkVoice system_instructions()
    ↓
  MR. STARK response
    ↓
  Display in console
    ↓
  speak_response() [TTS]
    ↓
  Audio output

VOICE MODE (NEW - CONTINUOUS):
  User speaks
    ↓
  VoiceCaptureWorker listening loop (runs continuously)
    ↓
  Speech Recognition captures complete utterance
    ↓
  utterance_captured signal emitted
    ↓
  _handle_voice_utterance() called
    ↓
  Text displayed in console as "You (voice): ..."
    ↓
  send_console_prompt() called WITH SAME TEXT
    ↓
  Gemini API with StarkVoice system_instructions()
    ↓
  MR. STARK response
    ↓
  Display in console as "MR. STARK: ..."
    ↓
  speak_response() [TTS]
    ↓
  microphone_suppressed = True (prevents echo)
    ↓
  Audio output
    ↓
  TTS finishes, microphone_suppressed = False
    ↓
  Worker automatically returns to listening loop
    ↓
  Repeat (or user presses Voice: Off)

UNIFIED PIPELINE:
  Both text and voice converge to send_console_prompt()
  Same Gemini system instructions applied
  Same conversation history shared
  Same response generation logic
  No duplication

SPEECH RECOGNITION PARAMETERS (TUNED)
======================================================================

energy_threshold = 4000
  - Adjusts microphone sensitivity
  - Value appropriate for normal conversation distances

dynamic_energy_threshold = True
  - Auto-adjusts for ambient noise
  - Adapts to different environments

pause_threshold = 0.8 seconds
  - Time of silence to detect end of utterance
  - Allows speaker to pause within sentences
  - Good balance between responsiveness and completeness

phrase_threshold = 0.3
  - Minimum confidence for considering audio a phrase
  - Lower value = more sensitive to quiet speech

non_speaking_duration = 0.5 seconds
  - Silence between phrases before considering utterance complete
  - Triggers end-of-speech detection

timeout = 12 seconds
  - Max time to wait for speech to start
  - Times out gracefully, returns to listening
  - Does not kill worker

phrase_time_limit = 15 seconds
  - Max length of a single utterance
  - Allows long thoughts but prevents infinite recording

======================================================================
ERROR HANDLING (ROBUST)
======================================================================

sr.UnknownValueError:
  → User sees: "Didn't catch that. Please repeat."
  → Worker: continues listening
  → Behavior: not fatal, try again

sr.RequestError:
  → User sees: "Connection issue: [error details]"
  → Worker: continues listening
  → Behavior: network error, but worker stays alive

sr.WaitTimeoutError:
  → User sees: "No speech detected. Still listening..."
  → Worker: continues listening
  → Behavior: user didn't speak in time, try again

microphone/audio exceptions:
  → User sees: "Voice error: [error details]"
  → Worker: continues listening
  → Behavior: audio device issue, but recovers

Fatal worker error:
  → User sees: "Voice worker error: [error details]"
  → Worker: emits worker_stopped signal
  → Behavior: unrecoverable error, worker exits cleanly

======================================================================
MICROPHONE SUPPRESSION (PREVENTS ECHO)
======================================================================

Flow:
  1. User speaks
  2. Worker captures "Hey Mr. Stark, build a robot"
  3. Worker emits utterance_captured
  4. _handle_voice_utterance() calls send_console_prompt()
  5. send_console_prompt() calls speak_response()
  6. speak_response() sets: self.microphone_suppressed = True
  7. During TTS playback, worker checks: if microphone_suppressed: sleep(0.1)
  8. TTS playback continues (Mr. Stark speaks)
  9. TTS finishes, speak_response() sets: self.microphone_suppressed = False
  10. Worker resumes listening
  11. IMPORTANT: Worker never hears Mr. Stark's own voice

Result: No feedback loop, no echo, clean audio capture

STATE MACHINE (CLEAN)
======================================================================

IDLE:
  - Voice OFF, worker not running
  - Microphone silent
  - Ready for text input or Voice: On

LISTENING:
  - Voice ON, worker in listening loop
  - Microphone active, waiting for speech
  - Worker emits listening signal regularly

PROCESSING:
  - Utterance captured
  - Microphone active but waiting for response
  - Sending to Gemini

THINKING:
  - (implicit during Gemini request)
  - UI shows processing state
  - No microphone input expected

SPEAKING:
  - TTS playing Mr. Stark's response
  - Microphone suppressed (no listening)
  - Worker sleeping (not checking for input)
  - Prevents echo/feedback

BACK TO LISTENING:
  - TTS finished
  - Suppression cleared
  - Worker resumes listening loop
  - Cycle repeats

ERROR:
  - Recognition error or audio error
  - User sees error message
  - Worker stays running
  - Automatically returns to listening
